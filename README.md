# Online Ordering System (Backend)
This is a minimal Online Ordering System (Backend), implemented fully in Java (Spring Framework).

This project is constructed with the purpose to improve, get used to the concepts of Spring MVC, JPA, Hibernate, JUnit and Mockito in writing unit tests. Neon (PostgreSQL) is used as the serverless database for the storage of this project. 

The project also has a frontend development. For the frontend of this project, please refer to this [repository](https://github.com/cukibe123/online-ordering-system-frontend)

If you are students or learners, who are learning Spring and want to understand more about what I have built in this project, feel free to hit me up!

# Core Concepts:
This system is built around four core domain concepts:
### 1. Table (Virtual Table)
* Represents a physical table in the restaurant.
* Exists permanently
* Has a stable token printed in the QR code
Does not store customer or order state

### 2. Visit
* Represents one seating / one bill at a table.
* Created when the first customer scans the QR code
* All customer sessions and orders belong to the same TableVisit
Closed when the invoice is printed
Prevents old orders from mixing with new customers
A table has many visits over time, but only one OPEN visit at a time.

### 3. Session
* Represents one customer on one device.
* Created every time a customer scans the QR code
* Identified by an opaque session token
* Multiple sessions can belong to the same TableVisit
Closed when the ``Visit`` is closed

### 4. Order

* Represents one order submission from a customer.
* Belongs to exactly one ``Session``
* Belongs to exactly one ``Visit``
Contains one or more order items

### 5. Invoice
* Represents one invoice at a table at one time
* Only one OPEN ``Invoice`` per ``Visit``
* Only one OPEN ``Invoice`` per ``Table``
Contains a summary of order items

# Authentication Model (Guest Sessions)
* Customers are not logged in
* Identity is established via a session token
* Token is generated by the backend, stored on the client, and sent on every request via HTTP header
From the backend, it resolves the session from the header using a filter.
